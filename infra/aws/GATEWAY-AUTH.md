# API Gateway authorizer + ECS Fargate

Production and staging client traffic uses the **existing API Gateway custom authorizer Lambda** as the only JWT gate. ECS tasks run with `AUTH_ENFORCEMENT=gateway` (set in CDK) so Nest does **not** register a duplicate global JWT guard.

## Request path (target)

```text
Client
  → API Gateway (custom authorizer Lambda)
  → VPC Link
  → private Application Load Balancer
  → Fargate task (edge :8080 → domain containers on localhost)
```

Handler-level authorization inside domains uses **`@qshelter/nest-auth`** (`RolesGuard`, `@Roles`, `AuthHelper`, `RequestHelper`).

## MOFI CDK stack today

The stack in [`lib/mofi-platform-api-stack.ts`](lib/mofi-platform-api-stack.ts) provisions:

- Fargate service + ALB (currently internet-facing for staging convenience)
- `AUTH_ENFORCEMENT=gateway` on all containers
- No JWT validation in the edge proxy container

## Public routes

Public path prefixes are defined once in [`libs/auth/src/authorizer-public-routes.ts`](../../libs/auth/src/authorizer-public-routes.ts) for **local dev only** (`AUTH_ENFORCEMENT=local`). In gateway mode, public routes are enforced only by the authorizer Lambda configuration—keep that Lambda config aligned with the shared list when routes change.

## Local development

```bash
# Default: AUTH_ENFORCEMENT=local → MofiAuthorizerGuard mirrors authorizer public paths
npm run start:dev

# Force gateway semantics (no global JWT guard in Nest)
AUTH_ENFORCEMENT=gateway npm run start:dev
```
